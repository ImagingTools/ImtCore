# Метаданные QML для редактора

[English version](README.en.md)

Цель `qml_tooling_metadata` описывает C++-типы, зарегистрированные процедурно
для QML, чтобы их видели `qmlls` и `qmllint`. Она принадлежит ImtCore и определена
в [Config/QmlTooling](../../Config/QmlTooling/CMakeLists.txt). Ни один продукт от
неё не зависит. Цель не входит в `ALL`, не компилирует и не линкует C++, не имеет
правил установки или развёртывания. Runtime-регистрации и импортные пути
приложений остаются без изменений.

## Генерация

Команды этого раздела выполняются из **корня репозитория ImtCore**.
Требуются Python 3.8 или новее и установленный Qt 6 для хост-системы с `moc`,
`qmltyperegistrar` и JSON-файлами метатипов. Используйте ту же установку Qt,
что и QML-инструменты редактора.

После повторной конфигурации существующей сборки ImtCore доступна команда:

```sh
cmake --build <imtcore-build-directory> --target qml_tooling_metadata
```

Можно настроить только эту цель, без конфигурации библиотек или продуктов:

```sh
cmake -S Config/QmlTooling -B out/qml-tooling-build \
    -DIMT_QML_TOOLING_QT_ROOT=/path/to/Qt/6.x/host-kit \
    -DIMT_QML_TOOLING_OUTPUT="$PWD/out/qml-tooling"
cmake --build out/qml-tooling-build --target qml_tooling_metadata
```

Либо запустить генератор напрямую, без CMake:

```sh
python3 Config/QmlTooling/generate.py \
    --qt-root /path/to/Qt/6.x/host-kit --output out/qml-tooling
```

Генератор определяет корень ImtCore по собственному расположению, а не по
рабочему каталогу. Параметры `--source-root` и `--manifest` позволяют явно
задать другие входные пути.

Параметры кеша CMake:

- `IMT_QML_TOOLING_QT_ROOT`: установка Qt для хост-системы; по умолчанию берётся
  из `QT_HOST_PATH` или расположения `Qt6::qmake`, если они доступны.
- `IMT_QML_TOOLING_PYTHON`: интерпретатор Python; по умолчанию используется
  `PYTHON_EXECUTABLE` либо найденный `python3`/`python`.
- `IMT_QML_TOOLING_OUTPUT`: корень импортов для редактора; по умолчанию
  `<build-directory>/qml-tooling`.

Добавьте абсолютный выходной путь в `qt-qml.qmlls.additionalImportPaths`, затем
выполните **Qt: Restart QML Language Server**. Не добавляйте этот каталог в
импортные пути приложения или в поставку продукта.

## Подключение Garden

Garden подключает цель ImtCore отдельно от графа зависимостей продуктов и
задаёт выходной каталог по умолчанию: `out/qml-tooling` в корне репозитория GMG.
Поэтому существующий импортный путь в настройках редактора сохраняется.
Из корня репозитория GMG генератор можно запустить так:

```sh
python3 3rdParty/ImtCore/Config/QmlTooling/generate.py \
    --qt-root /path/to/Qt/6.x/host-kit --output out/qml-tooling
```

## Добавление типов

[modules.json](../../Config/QmlTooling/modules.json) является центральным
реестром экспортов для инструментов. Начальное покрытие: все десять типов,
которые регистрируют два компонента-регистратора `imtqml` в модуле
`com.imtcore.imtqml` версии 1.0. Условные runtime-регистрации описываются как
доступные независимо от конфигурации ACF конкретного приложения.

Для нового модуля укажите URI, версию и список типов:

```json
{
    "uri": "example.models",
    "version": "1.0",
    "types": [
        {"name": "Model", "class": "example::CModel", "header": "Include/example/CModel.h"}
    ]
}
```

Пути заголовков задаются относительно **корня репозитория ImtCore**. Заголовок
должен содержать указанный класс с `Q_OBJECT` или `Q_GADGET`. Для singleton-типа
укажите `"singleton": true`, а для типа, экземпляры которого нельзя создавать
из QML, например контейнера перечислений, укажите `"uncreatable": true`.
Поддерживаются несколько классов в одном заголовке и экспорт одного класса
под разными URI. В текущем реестре каждому URI соответствует одна версия.

Если модуль также содержит QML-файлы, задайте `"qml_directory"`: путь от корня
ImtCore до каталога исходного модуля с `qmldir`. Генератор скопирует файлы в
отдельный выходной каталог и сохранит QML-экспорты. Без этого модуль с одними
метаданными скрыл бы исходный QML-модуль. Дополнительные библиотеки метатипов
Qt перечисляются в `"qt_modules"`, например `["Quick3D"]`. Core, Gui, Qml,
Quick, Network и WebSockets уже включены.

Добавляйте новые экспорты одновременно с runtime-регистрациями и повторно
запускайте цель. Свойства, сигналы и invokable-методы MOC извлекает из настоящих
заголовков. Генератор добавляет аннотации экспортов во временный MOC JSON,
запускает внутренний инструмент Qt `qmltyperegistrar` и удаляет созданный им
C++-код регистрации. Добавлять `QML_ELEMENT` или `QML_FOREIGN` в исходные
заголовки не требуется.

## Проверки и ограничения

Из корня репозитория ImtCore:

```sh
python3 -m unittest discover -s Config/QmlTooling -p 'test_generate.py'
```

Тесты сравнивают начальный реестр с runtime-регистрациями `imtqml`, поэтому
при запуске тестов новые экспорты этих компонентов не останутся незамеченными.

Генерация проверена на Qt 6.8.3 и 6.11.1. Внутренние JSON-форматы и интерфейсы
инструментов Qt могут меняться: после обновления Qt повторите проверки.
Заголовки, которым нужны сгенерированные include-файлы или макросы конкретной
сборки, требуют соответствующей поддержки препроцессинга MOC перед добавлением.
Сгенерированные C++-регистрации SDL автоматически не обнаруживаются.
